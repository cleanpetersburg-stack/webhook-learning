# Техническое задание: Webhook доставка событий

## 1. Регистрация и управление подписчиками

| Что описывать | Пример / Варианты |
|--------------|------------------|
| Кто хранит список подписчиков | Провайдер хранит у себя (в БД подписок) |
| Способ регистрации URL | REST API или UI |
| Как обновляется секрет | API-метод `PATCH /subscriptions/{id}/rotate-secret` |
| Тестовая отправка | При регистрации отправляется `test.webhook` |

## 2. Контракт вебхука

### HTTP метод и путь
- Метод: `POST`
- Путь: `/webhooks/orders` (указывает подписчик)

### Заголовки
| Заголовок | Назначение |
|-----------|------------|
| `X-Event-Id` | Уникальный ID события |
| `X-Signature` | HMAC-подпись |
| `X-Timestamp` | Защита от replay |
| `X-Correlation-Id` | Сквозная трассировка |

## 3. Семантика доставки и повторы

| Параметр | Значение |
|----------|----------|
| Гарантия доставки | `at-least-once` |
| Таймаут | 5 секунд |
| Ретраи | 5 попыток: 1,2,4,8,16 сек |
| DLQ | Тема Kafka `webhook.dlq` |

## 4. Идемпотентность

- Ключ: `(recipient_url, eventId)`
- TTL: 30 дней
- Повторная доставка с тем же `eventId` не должна вызывать повторный эффект

## 5. Ошибки и ответы

| Код | Действие |
|-----|----------|
| 2xx | Успех |
| 4xx | ❌ Не ретраим |
| 5xx | ✅ Ретраим |
| Таймаут | ✅ Ретраим |
